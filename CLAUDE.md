# drakepg

Browser turn-based RPG. Phaser 4 + TypeScript + Vite. See README.md for layout and content guides.

## Commands
- `npm run dev` / `npm run build` (build runs `tsc --noEmit` first) / `npm run typecheck`
- `npm run sim`: headless balance check (scripts/sim.ts). Run it after tuning monsters, skills, items or `BALANCE`.
- `npm run pace`: headless pacing estimate (scripts/pace.ts): rooms, fights, level at each boss, rough minutes per chapter. Run it after changing rooms or quests.
- Unity playthrough: `Drakepg.EditorTools.Playthrough.Run(20)` through the Unity MCP's `execute_code` (`unity/Assets/Editor/Playthrough.cs`): a bot that plays the whole story paying its own way (gold, potions, HP between fights, deaths and who caused them). Run it after changing the economy, drops, shops or monsters. Calls over ~30 s time out the MCP but keep running.

## Working across chats
Several chats (in the browser and on the PC) work on this repo and can't see each other. The repo is the only shared memory.
- **Start:** `git fetch`, then merge `origin/claude/sweet-cray-w6r64t` (the default branch, which GitHub Pages deploys) into your branch. Read `docs/PLANS.md` before planning anything.
- **Decisions:** when the user decides or proposes something, write it into `docs/PLANS.md` (Decided / Proposed / Open). When you build something from it, remove it there and log it in `docs/IMPROVEMENTS_2026-10.md`.
- **Finish:** nothing counts as done on a side branch. When the user OKs the work, merge it into the default branch (PR or local merge) and push, with `docs/PLANS.md` up to date. Never leave finished work only on a `claude/*` branch.
- If the user says "handoff", update `docs/PLANS.md`, merge and push, then reply with a short summary.

## Conventions
- Phaser 4, not 3. Before using an unfamiliar Phaser API, check `node_modules/phaser/skills/` (incl. `v3-to-v4-migration`) or `node_modules/phaser/types/phaser.d.ts`.
- Game rules in `src/game/` stay Phaser-free so they can be tested/simulated headless.
- Content is data in `src/data/`; add ids there, never hardcode content in scenes.
- Tuning numbers go in `BALANCE` in `src/config.ts`.
- Changing `PlayerData` requires bumping `SAVE_VERSION` and a `migrate()` step.
- Design space is 1280x720 (Scale.FIT, `DESIGN` in config.ts), but the canvas is `RES` times bigger to be sharp on big screens (`src/ui/view.ts`; 2 on 1440p, `?res=1` for the old canvas). Every scene's `create()` calls `enterScene(this)` (it zooms the camera by `RES`); switch scenes with `goTo()`. Lay out with `DESIGN`, never `scene.scale`; use `pointer.worldX/worldY`; camera shakes and zooms go through `shake()`/`zoomTo()` in view.ts; a second camera is `addOverlayCamera()`; DOM elements are placed by their top-left corner (`setOrigin(0)`).
- New heroes start on the one-way prologue road (`road_*` rooms, zone `road`) into Brindlemoor; chapter starts and saves with a lost location use `TOWN_START`. The road ends at a gate guard: a room `boss` with no `questId` (`byClass` picks a monster per class), fought once, `guarded` exits shut until it's beaten (`PlayerData.guardsBeaten`, rules in `src/game/Travel.ts`).
- Exploration is single-screen rooms (`RoomScene`, data in `ROOMS`). Depth = feet y. Monsters and chests on a map live in `session` (remembered per room for the play session: the dead stay dead, one wanders back per `BALANCE.respawnSeconds` away); only the player's location is saved. Per-browser preferences (story text) are in `src/game/settings.ts`, not the save.
- Map and travel: rooms carry a `map` spot (`src/data/map.ts` pages); `src/game/WorldMap.ts` builds what the map shows (visited rooms + "?" neighbours), `src/ui/mapPanel.ts` draws it (M / Map button). `PlayerData.visited` and `lastTown` (save v12) are set by `visitRoom()` in `src/game/Travel.ts`, which also has the Recall Scroll rules (`type: 'scroll'`; one way to `lastTown`'s `town` spot, not in battle). Quiet-room features are room data: `campfire` (one rest per visit, `session.restedAt`), `inspect`, `firstVisit` (letterboxed scene, drawn by a second camera), `side: 'down'` exits and a side room's sure `chest`; props are drawn in `src/ui/props.ts`. Chapter layout: 2-3 combat rooms, then a quiet room; the room before each boss is quiet with a campfire.
- One-shot keys use `keyboard.on('keydown-X')` (quick taps get lost with `JustDown` at low FPS); movement keys are polled.
- Effects live in `src/ui/fx.ts`; particle textures are generated at boot (no art needed). Battle hits use `elementBurst` per element; the battle HUD draws above effects (`HUD_DEPTH` in `BattleScene`). Status colors come from `StatusDef.tint`. Sounds are synthesized in `src/ui/sfx.ts` (`sfx.play(scene, name)`), no audio files.
- Combat: 8 elements (`src/data/elements.ts`), damage types melee/pierce/magic (STR/DEX/INT), statuses in `src/data/statuses.ts`, cooldowns and weapon procs in `src/game/Battle.ts`. Monster resist rule: +own element, -opposite. Weak spots besides elements: `weakTo` Blunt (skills with `blunt`) and Poison (bigger ticks), on the same "Weak:" line. Every mechanic must be visible in the battle UI or item text (no hidden specials). Monsters show their next move (`Battle.intent`); signature moves (`opener`/`every`/`hpBelow`) are described in the monster's `trait`. Resist over 100 absorbs. Long fights enrage (`BALANCE.enrage`). Heroic boss rematches: `src/game/Heroic.ts`.
- Weapons are drawn in the hero's hands: bare hero art + `look.bare.hands` pixel anchors (in 1x pixels, also for `@2x` art) + weapon `art/grip/size`. Re-measure anchors when bare art changes.
- One base hero for every class (`char_hero_bare`, `HERO_ART` in `src/data/classes.ts`); each class holds its weapon in its own fists (`look.bare.hands`). Top skills (`SkillDef.epic`) swap in drawn key poses in the Unity battle (`bare.poses`, art `char_hero_bare_<pose>` from `scripts/hero_poses.py`, same scale and feet as the base). Draw the hero with `player.look` (not `classDef.look`): body armor swaps the outfit to `<bare art minus _bare>_<armor id>` (`char_hero_scale_mail`) when that art exists; outfits are Qwen edits of the base at the same canvas, so the fists stay put (an armor's `hands[class]` overrides them).
- Cheats live in `src/game/cheats.ts` (rules, session-only toggles) and `src/ui/cheatMenu.ts` (backtick / tap the room name 5x). `cheats.rates` (x1-x10) multiplies XP/gold earned; wrap new drop chances in `boosted()` so the rates reach them. `LUCKY_ON_NEW_GAME` there is a testing switch (new characters meet a Lucky Impling); keep it off on the live branch.
- Lucky Implings (`src/game/Lucky.ts`, `BALANCE.lucky`): rare roaming spawn sized to its zone, runs from the player, `escapeAfter` makes it flee battle (`escaped` state/outcome). Sigil visuals (glow, motes, twinkles per tier) are `SIGIL_FX`/`animateSigilIcon` in `src/ui/itemUi.ts` and `sigilMotes` in `src/ui/figures.ts`.
- Equipment has 8 slots (`EQUIP_SLOTS`: weapon, helm, body, gloves, boots, necklace, ring1, ring2), plus `spare` (`ALL_SLOTS`, save v13): a second weapon whose lines don't count until swapped into the hand (`player.swapWeapons()`, `Battle.swapWeapon()` costs the turn; feature `weapon_swap`). Stats and sets read only `EQUIP_SLOTS`; anything listing owned gear uses `ALL_SLOTS`; `fitsSlot()` lets weapons into the spare slot. Armor has a `slot` (default body); rings/necklaces are `type: 'accessory'` whose numbers scale with their Power roll (`accessoryValue`). `slotsFor(def)` / `player.slotFor(def)` decide where a piece goes. Sets: `src/data/sets.ts` + `src/game/Sets.ts`; bonuses feed Player stats/HP/defense/crit/resists and `player.damageBonus` in Battle. Only body armor drives the outfit (`player.bodyArmor`).
- Gear has a `tier` (data) that caps its modifier lines (rolled lines + mods) via `BALANCE.modifierSlots` (helms, gloves, boots and jewelry get theirs from `tiered()` in `src/data/equipment.ts`; max 2 for now; a Sigil adds `BALANCE.sigils[tier].lines`). Gear gets stronger with roll stones from shops (`src/game/Stones.ts`); crafting/materials are disabled features for now; `rollKeys()`/`modSlots()` in `src/game/Items.ts` apply it.
- Gear is rolled: weapons/armor/accessories are unique `Gear` instances (`uid`, `itemId`, `rolls` 0-100 per line) in `PlayerData.gear`/`equipment`; consumables stack in `inventory`. Shop gear is 0%. Rules in `src/game/Items.ts`; item visuals, grade colors and compare in `src/ui/itemUi.ts`; the grid inventory and shop in `src/ui/inventory.ts`. Gear drops come from loot tables (`src/data/loot.ts`, monster `loot`), rolled as a cascade rare -> uncommon -> common (`BALANCE.loot`, `src/game/Loot.ts`); monster `drops` are for potions/materials only. Materials (`type: 'material'`) stack in `inventory` but take no bag slots; the smith (craft/reinforce/hone/salvage) is `src/game/Forge.ts` + `src/ui/forge.ts`, data in `src/data/crafting.ts`.
- New systems open chapter by chapter: add a `FeatureDef` to `src/data/features.ts` (unlocked by a quest) and gate code with `featureOn(player, id)` (`src/game/Features.ts`); it is announced once in the room's "New!" popup, like new skills.
- Skills: levels teach each class 6 (`ClassDef.skills`); every other skill is a skill book (`book_<skill>`, made in `src/data/items.ts`; read in the bag, learned into `PlayerData.learned`; rules `src/game/Books.ts` / `Rules/Books.cs`, spec `docs/BUILD_VARIETY_SPEC.md`). Book sources are data (shop `books`, quest and promotion `classBooks`, `ClassDef.heroicBook`, chest `book`, loot table `books`) and the spellbook's hints are built from them, so a new source needs no UI change. Element families (`FAMILIES`/`ELEMENT_EFFECTS` in skills.ts) are generated, never hand-written. Use `player.knownSkills`/`knowsSkill`, not `ClassDef.skills`. Which ones are carried into battle is `PlayerData.loadout` (`BALANCE.skillSlots`). Quest rules live in `src/game/Quests.ts`; quest state is `PlayerData.quests`. Quests are the story only (opener + bosses per chapter); errands are Adventurers' Guild hunts.
- The Spire (tower, `docs/TOWER_SPEC.md`): floors, twists, flights and vendor are data (`src/data/tower.ts`), rules `src/game/Tower.ts` / `Rules/Tower.cs`, numbers `BALANCE.tower`, save v17 `PlayerData.tower`. A floor's monster is built by `floorMonster` (moved up the level curve, twists applied, `MonsterDef.tower` for the battle options: starting statuses, enrage turn, no items); tower fights pay only through `clearFloor`. Unity: `TowerPanel`, the Warden (`role: { kind: 'tower' }`) in Spire Foot.
- Adventurers' Guild (`src/game/Guild.ts`, board UI `src/ui/guild.ts`, `BALANCE.guild`, save v15 `PlayerData.guild`): ranks F-S, a clerk NPC (`role: { kind: 'guild' }`) in each town sharing one board. Hunts aren't hand-written: they're built from reachable zones' monsters (kill, Elite bounty) and `ZoneDef.gather` items (gather; drops via `Battle.zoneId`). Hunt rank = monster level (`ranks[].minLevel`, +1 Tough/Elite); take up to `reach` ranks above yours. Story quests gate on `requiresRank` (status `'rank'`). Promotion rewards are `PROMOTIONS` in `src/data/guild.ts`.
- Art: raw images in `art/raw/` -> `python3 scripts/prepare_art.py` -> `src/assets/art/<key>@2x.webp` (2x: 2560x1440 backgrounds, 960px sprites; a too-small source or `--1x` gives `<key>.webp` at 1x), auto-loaded by key (`src/ui/art.ts`) and drawn at the 1x size, so 1x and 2x files mix. Sigil glows on item icons go through `glowIcon` (filtering a Container redraws the whole screen per icon). Missing art falls back to shapes. Sprites face right. Local generation: `scripts/redo_art.py` (ComfyUI + Qwen-Image 2.1 on the designer's PC, the round-15 look; tries in `art/redo/`, `pick key:seed`, `grips` for weapons; see IMPROVEMENTS "Art redo"); keys in `HAND_EDITED` are skipped by prepare_art unless `--force`.
- Original names/art only. No assets or names from Artix Entertainment games.
